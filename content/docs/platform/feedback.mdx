<Callout type="info" title="为什么没有伪造提交成功">
  反馈组件需要明确的持久化目标。当前示例站没有配置数据库、分析平台或 GitHub App，因此这里只完整保留官方接入写法，不把用户提交静默丢弃。
</Callout>

## 安装官方反馈组件

```npm
npx @fumadocs/cli@latest add feedback
```

CLI 会把组件源码安装到项目中，之后可以根据产品语言和后端接口进行调整。

## 页级反馈

在统一文档页面底部添加 `Feedback`，所有页面都会自动显示“有帮助 / 没帮助”一类的反馈入口：

```tsx title="app/docs/[[...slug]]/page.tsx"
import { Feedback } from '@/components/feedback/client';

<DocsPage>
  <DocsBody>{/* MDX 正文 */}</DocsBody>

  <Feedback
    onSendAction={async (feedback) => {
      'use server';

      await savePageFeedback(feedback);
    }}
  />
</DocsPage>
```

反馈对象通常包含：

```ts
{
  url: string;
  opinion: 'good' | 'bad';
  message: string;
}
```

## 内容块反馈

内容块反馈允许用户选中某一段文字后提交问题。首先启用块 ID 插件：

```ts title="source.config.ts"
import {
  remarkBlockId,
  type RemarkBlockIdOptions,
} from 'fumadocs-core/mdx-plugins/remark-block-id';

const blockIdOptions: RemarkBlockIdOptions = {
  addDataAttribute: 'feedback',
};

export default defineConfig({
  mdxOptions: {
    remarkPlugins: [
      [remarkBlockId, blockIdOptions],
    ],
  },
});
```

然后使用 `FeedbackText` 包住正文：

```tsx
import { FeedbackText } from '@/components/feedback/client';

<FeedbackText
  onSendAction={async (feedback) => {
    'use server';

    await saveBlockFeedback(feedback);
  }}
>
  <MDX components={getMDXComponents()} />
</FeedbackText>
```

内容块反馈通常还会包含：

```ts
{
  url: string;
  blockId: string;
  blockBody: string;
  message: string;
}
```

## 可选后端

| 目标 | 适用场景 |
| --- | --- |
| GitHub Discussions | 开源项目，反馈公开可追踪 |
| GitHub Issues | 希望每条问题进入现有 Issue 工作流 |
| Cloudflare D1 | 自建轻量反馈后台 |
| Supabase | 需要数据库、认证和管理后台 |
| PostHog | 同时分析页面评价与使用行为 |
| 邮件或 Webhook | 低频反馈和小型站点 |

## D1 数据表示例

```sql
CREATE TABLE documentation_feedback (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  page_url TEXT NOT NULL,
  feedback_type TEXT NOT NULL,
  opinion TEXT,
  message TEXT NOT NULL,
  block_id TEXT,
  block_body TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

## 在 MDX 中标记重点反馈区域

启用块级反馈后，普通段落会自动获得稳定块 ID。作者不需要在每篇文档中手写 ID；对于必须长期保持链接稳定的章节，仍建议给标题设置显式锚点：

```md
## 安装问题 [#installation-troubleshooting]
```

## 实施建议

- 先接入页级反馈，验证用户是否愿意提交。
- 再增加块级反馈，避免一开始让页面交互过重。
- 保存页面 URL、版本、语言和部署环境，便于定位问题。
- 对公开 GitHub 反馈进行敏感信息过滤和提交频率限制。
- 提交失败时明确提示，不要显示虚假的成功状态。

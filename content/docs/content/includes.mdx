# 一、先建立整体认识：高级语言最终在做什么

无论是 C、C++、Rust、Java，还是 Python，一条高级语言语句最终都必须转化为 CPU 能完成的几类基本操作：

1. 从内存读取数据；
2. 把数据写入内存；
3. 在寄存器中进行算术或逻辑运算；
4. 修改下一条要执行的指令地址；
5. 调用函数或返回；
6. 与操作系统、设备进行交互。

例如：

```c
int c = a + b;
```

从底层看，大致是：

```asm
mov eax, DWORD PTR [a]    ; 从内存读取 a
add eax, DWORD PTR [b]    ; eax = eax + b
mov DWORD PTR [c], eax    ; 把结果写入 c
```

CPU 并不知道“变量”“表达式”“循环”“对象”这些高级概念。

CPU 只知道：

* 寄存器；
* 内存地址；
* 指令；
* 标志位；
* 下一条指令地址。

# 二、汇编语言、机器语言和高级语言的关系

## 1. 机器语言

CPU 真正执行的是二进制机器指令。

例如在 x86-64 中：

```asm
mov eax, 1
```

可能编码为机器码：

```text
B8 01 00 00 00
```

汇编语言只是机器指令的文本表示形式。

```text
高级语言
   ↓ 编译器
中间表示 IR
   ↓ 指令选择
汇编语言
   ↓ 汇编器
机器码
   ↓
CPU 执行
```

## 2. 汇编语言并不是唯一的语言

不同 CPU 架构有不同汇编语言：

* x86、x86-64：Intel、AMD 处理器；
* ARM、AArch64：手机、Apple Silicon、服务器；
* RISC-V：开放指令集；
* MIPS：教学和嵌入式系统。

下面主要使用 **x86-64 Intel 语法**。

虽然具体寄存器名和指令不同，但高级语言转换为底层代码的基本思想是相通的。

# 三、CPU 执行程序时的基本状态

执行一个程序时，可以把 CPU 的状态简化为：

[
\text{CPU 状态}
=============

\text{寄存器}
+
\text{标志位}
+
\text{指令地址}
+
\text{内存}
]

## 1. 通用寄存器

x86-64 常见寄存器：

| 64 位  | 32 位  | 16 位  | 8 位低位 |
| ----- | ----- | ----- | ----- |
| `rax` | `eax` | `ax`  | `al`  |
| `rbx` | `ebx` | `bx`  | `bl`  |
| `rcx` | `ecx` | `cx`  | `cl`  |
| `rdx` | `edx` | `dx`  | `dl`  |
| `rsi` | `esi` | `si`  | `sil` |
| `rdi` | `edi` | `di`  | `dil` |
| `r8`  | `r8d` | `r8w` | `r8b` |
| ...   | ...   | ...   | ...   |

它们并不是四组不同的寄存器，而是同一个寄存器的不同部分。

例如：

```asm
mov rax, 0x1122334455667788
```

此时：

```text
rax = 0x1122334455667788
eax =         0x55667788
 ax =             0x7788
 al =               0x88
```

在 x86-64 中，写入 32 位寄存器会自动把对应 64 位寄存器的高 32 位清零：

```asm
mov eax, 1
```

执行后：

```text
rax = 0x0000000000000001
```

## 2. 特殊寄存器

### `rip`：指令指针

`rip` 保存下一条要执行的指令地址。

高级语言中的：

* `if`
* `while`
* `for`
* `break`
* `continue`
* 函数调用

本质上都与修改 `rip` 有关。

### `rsp`：栈顶指针

`rsp` 指向当前调用栈的栈顶。

### `rbp`：栈帧基址

传统上用于访问函数参数和局部变量。不过优化后的程序经常不使用 `rbp`，而是直接通过 `rsp` 或其他寄存器寻址。

# 四、CPU 如何执行一条指令

经典过程可以概括为：

1. 取指：根据 `rip` 从内存或指令缓存获取机器码；
2. 译码：判断是什么指令、有哪些操作数；
3. 执行：进行算术、访存或跳转；
4. 写回：把结果写回寄存器或内存；
5. 更新 `rip`。

现代 CPU 实际上还有：

* 多级流水线；
* 乱序执行；
* 分支预测；
* 寄存器重命名；
* 多级缓存；
* 微操作；
* 推测执行。

因此，汇编指令是 CPU 提供给程序员的**指令集架构接口**，不一定等于 CPU 内部真正执行的单个硬件动作。

# 五、数据在内存中如何保存

内存可以看成一个巨大的字节数组：

```text
地址       内容
0x1000    0x78
0x1001    0x56
0x1002    0x34
0x1003    0x12
```

如果从地址 `0x1000` 读取一个 32 位整数，在小端序机器上得到：

```text
0x12345678
```

因为 x86 使用小端序：低有效字节存放在低地址。

## 1. 常见数据大小

| 类型示例        | 常见大小 |
| ----------- | ---: |
| `char`      | 1 字节 |
| `short`     | 2 字节 |
| `int`       | 4 字节 |
| `long long` | 8 字节 |
| 指针          | 8 字节 |
| `float`     | 4 字节 |
| `double`    | 8 字节 |

这些大小受到语言、平台和 ABI 的影响，并非所有平台都完全相同。

## 2. 汇编中的大小说明

```asm
mov al, BYTE PTR [x]       ; 读取 1 字节
mov ax, WORD PTR [x]       ; 读取 2 字节
mov eax, DWORD PTR [x]     ; 读取 4 字节
mov rax, QWORD PTR [x]     ; 读取 8 字节
```

# 六、变量的底层本质

高级语言中的变量，本质上通常是以下三种情况之一：

1. 数据保存在寄存器中；
2. 数据保存在栈内存中；
3. 数据保存在全局区或堆内存中。

例如：

```c
int x = 10;
int y = x + 2;
```

没有优化时可能生成：

```asm
mov DWORD PTR [rbp-4], 10
mov eax, DWORD PTR [rbp-4]
add eax, 2
mov DWORD PTR [rbp-8], eax
```

有优化时可能直接变成：

```asm
mov eax, 12
```

甚至整个变量都不存在。

因此，源代码中的“变量”并不一定对应一个固定内存位置。编译器可能：

* 把变量放入寄存器；
* 将变量替换成常量；
* 删除没有作用的变量；
* 将多个变量复用同一寄存器；
* 完全消除某个表达式。

# 七、立即数、寄存器和内存操作数

汇编指令的操作数通常有三类。

## 1. 立即数

立即写在指令里的常量：

```asm
mov eax, 10
add eax, 3
```

其中 `10` 和 `3` 是立即数。

## 2. 寄存器

```asm
mov eax, ebx
add eax, ecx
```

## 3. 内存操作数

```asm
mov eax, DWORD PTR [rbx]
mov ecx, DWORD PTR [rbx+4]
```

方括号表示访问内存地址。

```asm
mov eax, ebx
```

表示复制寄存器中的数值。

```asm
mov eax, DWORD PTR [rbx]
```

表示把 `rbx` 当作地址，从这个地址读取 4 字节。

这正是“值”和“指针”的根本区别。

# 八、赋值语句的底层原理

考虑：

```c
x = y;
```

如果 `x`、`y` 都在内存中：

```asm
mov eax, DWORD PTR [y]
mov DWORD PTR [x], eax
```

大多数 x86 指令不能同时让源操作数和目标操作数都是普通内存，因此通常先读取到寄存器，再写入另一个内存位置。

## 复合赋值

```c
x += 3;
```

可能变成：

```asm
add DWORD PTR [x], 3
```

或者：

```asm
mov eax, DWORD PTR [x]
add eax, 3
mov DWORD PTR [x], eax
```

## 左值与右值

在：

```c
x = y + 1;
```

* `x` 需要提供一个可写入的位置，即地址；
* `y + 1` 需要提供一个计算结果，即数值。

可以粗略理解为：

* 左值关注“存到哪里”；
* 右值关注“值是多少”。

例如：

```c
*p = x;
```

底层逻辑是：

1. 取得指针 `p` 中保存的地址；
2. 取得 `x` 的值；
3. 把 `x` 写入 `p` 指向的地址。

```asm
mov rax, QWORD PTR [p]
mov ecx, DWORD PTR [x]
mov DWORD PTR [rax], ecx
```

# 九、整数表达式如何执行

## 1. 加减法

```c
result = a + b - c;
```

可能变成：

```asm
mov eax, DWORD PTR [a]
add eax, DWORD PTR [b]
sub eax, DWORD PTR [c]
mov DWORD PTR [result], eax
```

## 2. 乘法

```c
result = a * b;
```

```asm
mov eax, DWORD PTR [a]
imul eax, DWORD PTR [b]
mov DWORD PTR [result], eax
```

`imul` 通常用于有符号整数乘法。

## 3. 除法

x86 整数除法比加法复杂。

例如计算：

```c
int q = a / b;
int r = a % b;
```

可能生成：

```asm
mov eax, DWORD PTR [a]
cdq
idiv DWORD PTR [b]
mov DWORD PTR [q], eax
mov DWORD PTR [r], edx
```

在 32 位有符号除法中：

* 被除数位于 `edx:eax`；
* 商放入 `eax`；
* 余数放入 `edx`；
* `cdq` 把 `eax` 的符号扩展到 `edx`。

数学上：

[
a=bq+r
]

其中 `idiv` 同时计算商和余数。

# 十、补码和整数溢出

现代计算机通常使用补码表示有符号整数。

对于 (n) 位整数，取值范围是：

[
-2^{n-1}\leq x\leq 2^{n-1}-1
]

例如 8 位有符号整数范围：

[
-128\leq x\leq 127
]

`-1` 的 8 位补码为：

```text
11111111
```

32 位的 `-1` 为：

```text
FFFFFFFF
```

## 为什么加法器可以同时处理正负数

例如 8 位：

```text
  00000001   1
+ 11111111  -1
-----------
1 00000000
```

最高位进位被丢弃，结果为 0。

所以 CPU 不需要单独设计“负数加法器”。同一个二进制加法电路可以处理补码加法。

## 有符号和无符号的位模式相同

位模式：

```text
11111111
```

解释为无符号数：

[
255
]

解释为 8 位补码：

[
-1
]

底层位模式没有变，变化的是程序如何解释它。

# 十一、位运算对应什么

```c
x = a & b;
x = a | b;
x = a ^ b;
x = ~a;
x = a << 2;
x = a >> 2;
```

分别对应：

```asm
and eax, ebx
or  eax, ebx
xor eax, ebx
not eax
shl eax, 2
sar eax, 2
```

右移需要区分：

* `shr`：逻辑右移，高位补 0；
* `sar`：算术右移，高位补符号位。

例如：

```text
11110000
```

逻辑右移一位：

```text
01111000
```

算术右移一位：

```text
11111000
```

# 十二、复杂表达式的计算过程

考虑：

```c
x = (a + b) * (c - d);
```

一种直接翻译是：

```asm
mov eax, DWORD PTR [a]
add eax, DWORD PTR [b]     ; eax = a + b

mov ecx, DWORD PTR [c]
sub ecx, DWORD PTR [d]     ; ecx = c - d

imul eax, ecx              ; eax = (a+b)*(c-d)
mov DWORD PTR [x], eax
```

表达式树大致是：

```text
          *
        /   \
       +     -
      / \   / \
     a   b c   d
```

编译器会遍历表达式树，将中间结果保存在：

* 寄存器；
* 临时栈空间；
* 编译器中间表示的虚拟寄存器。

## 运算符优先级去哪了

优先级只用于编译阶段解析源代码。

编译器已经把：

```c
a + b * c
```

解析成：

```text
a + (b * c)
```

生成汇编后，CPU 不再知道运算符优先级，只是按照指令执行：

```asm
mov eax, DWORD PTR [b]
imul eax, DWORD PTR [c]
add eax, DWORD PTR [a]
```

# 十三、自增和自减

考虑：

```c
x++;
```

可能是：

```asm
add DWORD PTR [x], 1
```

前置和后置自增的区别不在“是否加一”，而在表达式结果取旧值还是新值。

## 后置自增

```c
y = x++;
```

逻辑上：

1. 保存旧的 `x`；
2. `x` 加一；
3. 把旧值赋给 `y`。

```asm
mov eax, DWORD PTR [x]
lea ecx, [eax+1]
mov DWORD PTR [x], ecx
mov DWORD PTR [y], eax
```

## 前置自增

```c
y = ++x;
```

```asm
mov eax, DWORD PTR [x]
add eax, 1
mov DWORD PTR [x], eax
mov DWORD PTR [y], eax
```

---

# 十四、标志寄存器和比较

x86 CPU 有一组状态标志位，常见的包括：

| 标志位  | 含义       |
| ---- | -------- |
| `ZF` | 结果是否为 0  |
| `SF` | 结果的符号位   |
| `CF` | 无符号进位或借位 |
| `OF` | 有符号溢出    |
| `PF` | 低字节奇偶校验  |

## `cmp` 指令

```asm
cmp eax, ebx
```

在内部相当于计算：

[
eax-ebx
]

但不保存减法结果，只更新标志位。

随后条件跳转指令根据标志位决定是否跳转。

## 有符号和无符号比较

例如：

```asm
cmp eax, ebx
```

之后：

| 指令    | 含义      |
| ----- | ------- |
| `je`  | 相等      |
| `jne` | 不相等     |
| `jl`  | 有符号小于   |
| `jle` | 有符号小于等于 |
| `jg`  | 有符号大于   |
| `jge` | 有符号大于等于 |
| `jb`  | 无符号小于   |
| `jbe` | 无符号小于等于 |
| `ja`  | 无符号大于   |
| `jae` | 无符号大于等于 |

为什么同一次 `cmp` 能支持两种比较？

因为 CPU 同时设置了：

* `CF` 等适合无符号解释的标志；
* `SF`、`OF` 等适合有符号解释的标志。

不同跳转指令读取不同标志组合。

# 十五、关系表达式如何得到 0 或 1

高级语言：

```c
int x = a < b;
```

可能生成：

```asm
cmp eax, ebx
setl al
movzx eax, al
```

`setl al` 会根据有符号“小于”条件，将 `al` 设置为 0 或 1。

`movzx` 再把 8 位的 `al` 零扩展到 32 位 `eax`。

因此关系表达式：

```c
a < b
```

底层可以有两种使用方式：

1. 直接用于跳转；
2. 转换为整数 0 或 1。

# 十六、`if` 语句的底层原理

高级语言：

```c
if (x > 0) {
    y = 1;
} else {
    y = -1;
}
```

汇编结构：

```asm
cmp DWORD PTR [x], 0
jle else_branch

mov DWORD PTR [y], 1
jmp end_if

else_branch:
mov DWORD PTR [y], -1

end_if:
```

本质结构是：

```text
计算条件
条件不成立 → 跳转到 else
执行 then
无条件跳转到结束
else:
执行 else
结束:
```

CPU 并没有专门的 `if` 指令。

`if` 只是：

* 比较；
* 条件跳转；
* 标签；
* 无条件跳转。

# 十七、条件运算符的底层原理

```c
x = condition ? a : b;
```

可以生成分支：

```asm
cmp DWORD PTR [condition], 0
je choose_b

mov eax, DWORD PTR [a]
jmp done

choose_b:
mov eax, DWORD PTR [b]

done:
mov DWORD PTR [x], eax
```

也可能使用条件移动指令：

```asm
mov eax, DWORD PTR [b]
mov ecx, DWORD PTR [a]
cmp DWORD PTR [condition], 0
cmovne eax, ecx
```

`cmovne` 表示条件不等时移动。

条件移动可以避免分支预测失败，但它并不一定总是更快，编译器会综合考虑。

# 十八、逻辑与、逻辑或和短路求值

## 1. 逻辑与 `&&`

```c
if (a != 0 && b != 0) {
    work();
}
```

底层必须体现短路：

```asm
cmp DWORD PTR [a], 0
je end_if

cmp DWORD PTR [b], 0
je end_if

call work

end_if:
```

当 `a == 0` 时，根本不会求值 `b != 0`。

## 2. 逻辑或 `||`

```c
if (a != 0 || b != 0) {
    work();
}
```

```asm
cmp DWORD PTR [a], 0
jne do_work

cmp DWORD PTR [b], 0
je end_if

do_work:
call work

end_if:
```

## 为什么这很重要

```c
if (p != NULL && p->value > 0)
```

必须先检查 `p`，只有 `p` 非空才允许读取 `p->value`。

短路求值本质上是控制流，而不是普通的按位运算。

所以：

```c
a && b
```

和：

```c
a & b
```

含义不同。

# 十九、`while` 循环的底层原理

```c
while (x < 10) {
    x++;
}
```

可以翻译为：

```asm
loop_begin:
cmp DWORD PTR [x], 10
jge loop_end

add DWORD PTR [x], 1
jmp loop_begin

loop_end:
```

循环没有神秘之处，本质上就是：

```text
循环开始:
    判断条件
    不满足则跳出
    执行循环体
    跳回循环开始
循环结束:
```

---

# 二十、`do...while` 循环

```c
do {
    x++;
} while (x < 10);
```

汇编结构：

```asm
loop_begin:
add DWORD PTR [x], 1

cmp DWORD PTR [x], 10
jl loop_begin
```

和 `while` 的区别在于：

* `while` 先判断后执行；
* `do...while` 先执行后判断。

所以 `do...while` 至少执行一次。

---

# 二十一、`for` 循环

```c
for (int i = 0; i < 10; i++) {
    sum += i;
}
```

可以改写成：

```c
int i = 0;
while (i < 10) {
    sum += i;
    i++;
}
```

对应汇编：

```asm
mov DWORD PTR [i], 0

loop_test:
cmp DWORD PTR [i], 10
jge loop_end

mov eax, DWORD PTR [i]
add DWORD PTR [sum], eax

add DWORD PTR [i], 1
jmp loop_test

loop_end:
```

所以 `for` 并不是 CPU 的特殊循环结构，只是语法糖。

---

# 二十二、`break` 和 `continue`

```c
while (condition) {
    if (a)
        break;

    if (b)
        continue;

    work();
}
```

可以理解为：

```asm
loop_test:
; 判断 condition
; 不满足跳到 loop_end

; 判断 a
; 成立跳到 loop_end

; 判断 b
; 成立跳到 loop_continue

call work

loop_continue:
jmp loop_test

loop_end:
```

因此：

* `break`：跳转到循环结束标签；
* `continue`：跳转到下一轮判断或更新位置。

在 `for` 循环中，`continue` 通常跳到更新表达式，而不是直接跳到条件判断。

# 二十三、`switch` 语句

```c
switch (x) {
case 1:
    a();
    break;
case 2:
    b();
    break;
case 3:
    c();
    break;
default:
    d();
}
```

## 情况一：比较链

分支较少时可能生成：

```asm
cmp eax, 1
je case_1

cmp eax, 2
je case_2

cmp eax, 3
je case_3

jmp default_case
```

## 情况二：跳转表

当 case 值比较密集时，可以使用跳转表。

假设 `x` 的范围是 1 到 3：

```asm
sub eax, 1
cmp eax, 2
ja default_case

jmp QWORD PTR [jump_table + rax*8]
```

跳转表：

```asm
jump_table:
dq case_1
dq case_2
dq case_3
```

地址计算为：

[
\text{目标地址}
===========

\text{跳转表基地址}
+
\text{索引}\times 8
]

因为在 64 位系统中，每个代码地址通常占 8 字节。

# 二十四、数组访问的底层原理

```c
int x = arr[i];
```

若每个 `int` 占 4 字节，则：

[
\operatorname{address}(arr[i])
==============================

\operatorname{base}(arr)
+
i\times 4
]

在 Windows x64 调用约定中，假设：

* `rcx` 保存数组首地址；
* `rdx` 保存索引 `i`。

可以写：

```asm
mov eax, DWORD PTR [rcx + rdx*4]
```

x86 支持的典型寻址形式是：

[
\text{有效地址}
===========

\text{基址}
+
\text{索引}\times\text{比例}
+
\text{偏移}
]

比例通常可以是：

[
1,\ 2,\ 4,\ 8
]

例如：

```asm
mov eax, DWORD PTR [rbx + rcx*4 + 8]
```

表示从地址：

[
rbx+4rcx+8
]

读取 4 字节。

## 二维数组

```c
int a[3][4];
int x = a[i][j];
```

按行存储时：

[
\operatorname{address}(a[i][j])
===============================

\operatorname{base}(a)
+
(i\times 4+j)\times 4
]

一般形式：

[
\operatorname{address}(a[i][j])
===============================

\operatorname{base}(a)
+
(i\times \text{列数}+j)\times \operatorname{sizeof}(T)
]

CPU 并不知道“二维数组”，只是在计算一个线性地址。

# 二十五、指针的底层本质

指针变量本身也是一个整数形式的值，只不过这个值被解释为内存地址。

```c
int x = 10;
int *p = &x;
int y = *p;
```

逻辑过程：

```asm
lea rax, [x]
mov QWORD PTR [p], rax

mov rcx, QWORD PTR [p]
mov edx, DWORD PTR [rcx]
mov DWORD PTR [y], edx
```

## `lea` 指令

`lea` 是 Load Effective Address，即加载有效地址。

```asm
lea rax, [rbx+rcx*4]
```

不是读取该地址中的数据，而是计算：

[
rax=rbx+4rcx
]

比较：

```asm
mov eax, DWORD PTR [rbx]
```

含义是读取 `rbx` 指向的内存。

```asm
lea rax, [rbx]
```

含义是把地址值 `rbx` 复制到 `rax`。

## 指针加一

```c
int *p;
p++;
```

由于 `int` 占 4 字节，实际是：

```asm
add p, 4
```

一般来说：

[
p+n
]

实际地址变化量是：

[
n\times \operatorname{sizeof}(*p)
]

# 二十六、结构体的底层原理

```c
struct Student {
    int id;
    char grade;
    double score;
};
```

结构体对象本质上是一段连续内存，每个字段位于固定偏移。

一种可能布局：

```text
偏移 0：id       4 字节
偏移 4：grade    1 字节
偏移 5～7：填充
偏移 8：score    8 字节
总大小：16 字节
```

访问：

```c
student.id
student.score
```

可能对应：

```asm
mov eax, DWORD PTR [rcx+0]
movsd xmm0, QWORD PTR [rcx+8]
```

其中 `rcx` 是结构体地址。

## 为什么存在填充

因为许多数据类型需要按照特定边界对齐。

例如 `double` 通常希望地址是 8 的倍数，因此编译器可能在 `grade` 后面插入 3 字节填充。

这就是为什么：

```c
sizeof(struct Student)
```

不一定等于各字段大小简单相加。

# 二十七、函数调用的底层原理

高级语言：

```c
int result = add(2, 3);
```

函数：

```c
int add(int a, int b) {
    return a + b;
}
```

在 Windows x64 调用约定中，前四个整数参数通常依次使用：

```text
rcx, rdx, r8, r9
```

返回值通常放在：

```text
rax
```

因此 `add` 可能是：

```asm
add:
    mov eax, ecx
    add eax, edx
    ret
```

调用者：

```asm
mov ecx, 2
mov edx, 3
call add
; eax 中是返回值 5
```

## `call` 做了什么

简化理解：

1. 把返回地址压入栈；
2. 把 `rip` 修改为被调用函数的地址。

近似等价于：

```text
push 返回地址
jmp 函数地址
```

## `ret` 做了什么

1. 从栈中弹出返回地址；
2. 把该地址写入 `rip`。

近似等价于：

```text
pop rip
```

因此函数调用本质上也是一次特殊跳转，只是额外保存了返回位置。

# 二十八、不同平台的参数寄存器

常见 x86-64 调用约定：

| 平台                   | 前几个整数参数                      |
| -------------------- | ---------------------------- |
| Windows x64          | `rcx, rdx, r8, r9`           |
| Linux/macOS System V | `rdi, rsi, rdx, rcx, r8, r9` |

因此，同一个 C 函数在 Windows 和 Linux 下生成的汇编可能不同。

调用约定还规定了：

* 参数放在哪里；
* 返回值放在哪里；
* 哪些寄存器由调用者保存；
* 哪些寄存器由被调用者保存；
* 栈如何对齐；
* 结构体如何传递；
* 浮点参数如何传递。

调用约定是不同模块能够互相调用的基础。

# 二十九、函数栈帧

没有优化时，一个函数可能有如下结构：

```asm
function:
    push rbp
    mov rbp, rsp
    sub rsp, 32

    ; 函数体

    mov rsp, rbp
    pop rbp
    ret
```

进入函数：

```asm
push rbp
mov rbp, rsp
sub rsp, 32
```

含义是：

1. 保存调用者的 `rbp`；
2. 建立当前函数的栈帧基址；
3. 为局部变量分配 32 字节空间。

局部变量可以位于：

```text
[rbp-4]
[rbp-8]
[rbp-16]
```

参数或调用者数据可能位于：

```text
[rbp+8]
[rbp+16]
```

不过在优化后的程序中：

* `rbp` 可能被当作普通寄存器使用；
* 局部变量可能完全在寄存器中；
* 栈帧可能不存在；
* 函数可能被内联，不再真正调用。

# 三十、局部变量为什么通常在栈中

例如：

```c
void f() {
    int x = 10;
    int y = 20;
}
```

进入函数时调整：

```asm
sub rsp, 16
```

离开函数时恢复：

```asm
add rsp, 16
ret
```

栈分配非常快，因为通常只需修改 `rsp`。

分配 (n) 字节：

[
rsp\leftarrow rsp-n
]

释放：

[
rsp\leftarrow rsp+n
]

但“局部变量一定在栈中”并不准确。编译器优先让经常使用的局部变量保存在寄存器中。

只有在以下情况下更可能真正放入内存：

* 寄存器不够；
* 变量地址被取出；
* 变量需要跨函数调用保存；
* 调试构建需要保留清晰映射；
* 变量是较大的数组或结构体。

# 三十一、堆内存和动态分配

```c
int *p = malloc(sizeof(int));
*p = 10;
free(p);
```

汇编层面大致是：

```asm
mov ecx, 4
call malloc

mov DWORD PTR [rax], 10

mov rcx, rax
call free
```

CPU 本身不提供 `malloc` 指令。

`malloc` 是运行库函数，它管理进程虚拟地址空间中的一部分区域。

它可能维护：

* 空闲链表；
* 内存块头部；
* 大小分类；
* 内存页；
* 线程缓存。

高级语言中的 `new` 也通常是：

1. 调用分配器获得内存；
2. 初始化对象；
3. 调用构造函数。

垃圾回收语言则由运行时跟踪对象是否仍可访问，在适当时候回收内存。

# 三十二、函数参数为什么有值传递和引用传递

## 1. 值传递

```c
void f(int x) {
    x = 10;
}
```

调用者把数值复制到参数寄存器或栈中。

修改函数内的 `x` 不会直接修改调用者变量。

## 2. 指针传递

```c
void f(int *p) {
    *p = 10;
}
```

调用者传递变量地址。

```asm
; rcx = p
mov DWORD PTR [rcx], 10
```

## 3. C++ 引用

```cpp
void f(int& x) {
    x = 10;
}
```

在多数实现中，引用参数底层与指针相似，只是语法和语言规则不同。

也就是说：

```cpp
f(a);
```

编译器实际上传递了 `a` 的地址。

# 三十三、递归的底层原理

```c
int factorial(int n) {
    if (n <= 1)
        return 1;
    return n * factorial(n - 1);
}
```

每次递归调用都会产生新的函数调用状态：

```text
factorial(4)
  factorial(3)
    factorial(2)
      factorial(1)
```

栈中可能依次保存：

* 返回地址；
* 参数；
* 局部变量；
* 需要保留的寄存器。

返回过程：

```text
factorial(1) = 1
factorial(2) = 2 × 1
factorial(3) = 3 × 2
factorial(4) = 4 × 6
```

递归并不是 CPU 的特殊功能，只是函数在返回前又调用了自身。

递归层数过深导致“栈溢出”，是因为每层调用都占用一定栈空间。

# 三十四、字符串的底层表示

## C 字符串

```c
char s[] = "abc";
```

内存中通常是：

```text
'a' 'b' 'c' '\0'
61  62  63  00
```

字符串长度需要不断查找结尾的 `0`。

```c
strlen(s)
```

核心逻辑类似：

```asm
xor eax, eax

loop:
cmp BYTE PTR [rcx+rax], 0
je done

inc rax
jmp loop

done:
```

## 高级语言字符串

Java、C#、Python、JavaScript 的字符串通常是运行时对象，可能包含：

* 类型信息；
* 长度；
* 字符数据地址；
* 哈希缓存；
* 编码信息；
* 引用计数或垃圾回收信息。

所以高级语言的一次字符串拼接，底层可能涉及：

* 计算新长度；
* 分配堆内存；
* 复制多个字符串；
* 创建新对象；
* 更新引用或垃圾回收状态。

# 三十五、浮点表达式的底层原理

现代 x86-64 通常使用 SSE/AVX 寄存器：

```text
xmm0, xmm1, xmm2, ...
ymm0, ymm1, ...
```

例如：

```c
double c = a + b;
```

可能生成：

```asm
movsd xmm0, QWORD PTR [a]
addsd xmm0, QWORD PTR [b]
movsd QWORD PTR [c], xmm0
```

常见指令：

| 指令        | 含义      |
| --------- | ------- |
| `addss`   | 单精度浮点加法 |
| `addsd`   | 双精度浮点加法 |
| `mulss`   | 单精度浮点乘法 |
| `mulsd`   | 双精度浮点乘法 |
| `divsd`   | 双精度浮点除法 |
| `ucomisd` | 双精度浮点比较 |

浮点数通常遵循 IEEE 754，数值可抽象表示为：

[
(-1)^s\times 1.f\times 2^e
]

它不能精确表示所有十进制小数，所以：

```c
0.1 + 0.2
```

在二进制浮点中通常不能精确等于数学意义上的 `0.3`。

此外，浮点比较还必须处理：

* 正无穷；
* 负无穷；
* 正零；
* 负零；
* NaN；
* 非规格化数。

# 三十六、类和对象如何映射到底层

考虑 C++：

```cpp
class Point {
public:
    int x;
    int y;

    int sum() {
        return x + y;
    }
};
```

对象本质上类似结构体：

```text
偏移 0：x
偏移 4：y
```

调用：

```cpp
p.sum();
```

实际会隐式传入 `this` 指针。

概念上相当于：

```cpp
Point_sum(&p);
```

函数可能是：

```asm
; rcx = this
mov eax, DWORD PTR [rcx]
add eax, DWORD PTR [rcx+4]
ret
```

## 成员函数通常不存放在每个对象中

对象中通常保存成员数据。

成员函数的机器码存放在代码区，调用时传入对象地址。

因此，创建 1000 个普通对象并不意味着复制 1000 份成员函数代码。

# 三十七、虚函数和动态绑定

C++ 虚函数通常使用虚函数表。

```cpp
class Animal {
public:
    virtual void speak();
};
```

对象中可能含有隐藏的虚表指针：

```text
对象：
+0   vptr
+8   其他字段
```

虚表中存放函数地址：

```text
vtable:
[0] Animal::speak 地址
[1] Animal::run 地址
```

虚函数调用：

```cpp
animal->speak();
```

底层可能类似：

```asm
mov rax, QWORD PTR [rcx]       ; 读取 vptr
call QWORD PTR [rax]           ; 调用虚表中的函数
```

因此动态绑定本质上是：

1. 读取对象中的虚表地址；
2. 从虚表中读取目标函数地址；
3. 间接调用函数。

这比普通函数调用多了一到两次内存读取和一次间接跳转。

# 三十八、函数指针和回调

```c
int (*func)(int, int);
result = func(a, b);
```

底层是间接调用：

```asm
mov rax, QWORD PTR [func]
call rax
```

普通调用：

```asm
call add
```

目标地址在指令中直接确定。

函数指针调用：

```asm
call rax
```

目标地址运行时才确定。

高级语言中的以下机制经常依赖类似原理：

* 回调函数；
* 接口调用；
* 虚函数；
* 闭包；
* 事件监听；
* 动态分派。

# 三十九、闭包的底层原理

例如伪代码：

```javascript
function outer() {
    let x = 10;

    return function() {
        return x + 1;
    };
}
```

内部函数退出 `outer` 后仍需要访问 `x`，因此 `x` 不能只放在 `outer` 的普通栈帧中。

运行时可能创建一个环境对象：

```text
闭包对象：
- 函数代码地址
- 环境对象地址

环境对象：
- x = 10
```

调用闭包时，同时传入：

* 函数入口地址；
* 捕获变量环境地址。

所以闭包可以理解为：

[
\text{闭包}
=========

\text{函数代码}
+
\text{捕获环境}
]

# 四十、异常处理的底层原理

高级语言：

```cpp
try {
    work();
} catch (...) {
    handle();
}
```

异常通常不能简单理解为普通 `if`。

现代 C++ 常使用表驱动异常处理：

1. 正常执行时几乎没有额外分支；
2. 抛出异常时，运行时查找异常处理表；
3. 沿调用栈向上展开；
4. 销毁已经构造的局部对象；
5. 找到匹配的 `catch`；
6. 跳转到处理代码。

Java、C# 也有自己的异常表和运行时机制。

抛异常可能非常昂贵，但没有异常发生时，正常路径可以较轻量。

# 四十一、系统调用和普通函数调用的区别

普通函数调用仍然在用户态执行：

```asm
call printf
```

`printf` 内部最终可能需要请求操作系统输出数据。

操作系统提供系统调用，例如：

* 读取文件；
* 写文件；
* 创建进程；
* 分配虚拟内存；
* 网络通信。

系统调用需要从用户态切换到内核态。

在 x86-64 Linux 中常见：

```asm
syscall
```

CPU 会：

1. 切换权限级别；
2. 跳转到内核预设入口；
3. 执行内核代码；
4. 返回用户态。

所以：

```c
printf("hello");
```

底层可能经历：

```text
printf 格式化
    ↓
C 运行库缓冲
    ↓
write 系统调用
    ↓
内核
    ↓
终端或文件驱动
```

高级语言的一行代码可能对应非常复杂的运行时行为。

# 四十二、编译器是如何逐步降低抽象层次的

考虑：

```c
int max(int a, int b) {
    return a > b ? a : b;
}
```

## 1. 词法分析

识别：

```text
int
max
(
int
a
,
int
b
...
```

## 2. 语法分析

构建抽象语法树：

```text
Function max
├── Parameter a
├── Parameter b
└── Return
    └── Conditional
        ├── a > b
        ├── a
        └── b
```

## 3. 中间表示

编译器可能生成类似：

```text
if a > b goto L1
t = b
goto L2

L1:
t = a

L2:
return t
```

或者 SSA 形式：

```text
branch a > b, L1, L2

L1:
    goto L3(a)

L2:
    goto L3(b)

L3(v):
    return v
```

## 4. 指令选择

选择目标 CPU 指令：

```asm
cmp ecx, edx
mov eax, edx
cmovg eax, ecx
ret
```

## 5. 寄存器分配

决定变量放在哪些真实寄存器中。

## 6. 指令调度和优化

调整指令顺序，减少等待和寄存器冲突。

# 四十三、编译器常见优化

## 1. 常量折叠

```c
x = 2 * 3 + 4;
```

直接变成：

```c
x = 10;
```

汇编：

```asm
mov eax, 10
```

## 2. 死代码消除

```c
x = 10;
x = 20;
return x;
```

第一次赋值没有被使用，可能直接删除。

## 3. 公共子表达式消除

```c
x = a * b + 1;
y = a * b + 2;
```

`a * b` 可能只计算一次。

## 4. 强度削弱

```c
x = i * 8;
```

可能使用移位：

```asm
shl eax, 3
```

因为：

[
i\times 8=i\times 2^3=i\ll 3
]

不过现代 CPU 中乘法也很快，编译器会根据具体情况决定。

## 5. 循环不变量外提

```c
for (int i = 0; i < n; i++) {
    a[i] = x * y + i;
}
```

`x * y` 不随循环变化，可以提前计算：

```c
int temp = x * y;

for (int i = 0; i < n; i++) {
    a[i] = temp + i;
}
```

## 6. 函数内联

```c
int add1(int x) {
    return x + 1;
}

y = add1(a);
```

可能直接变成：

```c
y = a + 1;
```

不再生成 `call` 和 `ret`。

## 7. 自动向量化

```c
for (int i = 0; i < 4; i++) {
    c[i] = a[i] + b[i];
}
```

普通标量执行一次处理一个数。

向量化后，一条 SIMD 指令可以同时处理多个数：

```asm
movups xmm0, XMMWORD PTR [a]
addps xmm0, XMMWORD PTR [b]
movups XMMWORD PTR [c], xmm0
```

# 四十四、为什么源代码顺序不一定等于执行顺序

源代码：

```c
a = 1;
b = 2;
c = a + b;
```

编译器只需保证程序的**可观察行为**符合语言规则。

它可能：

* 调整无关指令顺序；
* 删除不影响结果的操作；
* 提前读取数据；
* 合并多次操作；
* 把变量留在寄存器中。

CPU 还可能进行乱序执行。

因此存在三种顺序：

1. 源代码顺序；
2. 编译器生成的机器指令顺序；
3. CPU 内部实际执行微操作的顺序。

单线程程序通常只观察到符合语言语义的最终结果。但在多线程环境中，需要：

* 原子操作；
* 内存屏障；
* 锁；
* 语言内存模型。

否则不同线程可能观察到意料之外的顺序。

---

# 四十五、汇编中的原子操作和锁

例如多个线程同时执行：

```c
counter++;
```

这个操作并不天然是原子的，它可能分解为：

```asm
mov eax, DWORD PTR [counter]
add eax, 1
mov DWORD PTR [counter], eax
```

两个线程可能同时读取旧值，导致更新丢失。

x86 可以使用带 `lock` 前缀的指令：

```asm
lock add DWORD PTR [counter], 1
```

或者：

```asm
lock xadd DWORD PTR [counter], eax
```

高级语言的原子变量、互斥锁和并发容器，最终依赖：

* 原子机器指令；
* 内存顺序规则；
* 操作系统调度；
* 等待与唤醒机制。

---

# 四十六、分支预测为什么影响 `if`

现代 CPU 使用流水线同时处理多条指令。

遇到：

```asm
cmp eax, 0
je label
```

CPU 在比较结果尚未完全确定时，可能先猜测是否跳转。

猜对：流水线继续高效运行。

猜错：已经推测执行的指令需要丢弃，并从正确地址重新取指。

这就是分支预测失败代价。

例如数据几乎总是有序时：

```c
if (x > 0)
```

预测可能很准。

若条件完全随机：

```c
if (random_bit)
```

预测更困难。

但不能简单认为“无分支代码一定更快”，因为条件移动和额外计算也有成本。

# 四十七、缓存如何影响数组和链表

CPU 访问寄存器最快，访问主存很慢，因此存在缓存：

```text
寄存器
  ↓
L1 Cache
  ↓
L2 Cache
  ↓
L3 Cache
  ↓
主存
```

数组：

```c
for (int i = 0; i < n; i++)
    sum += a[i];
```

内存连续，缓存友好。

链表：

```c
for (Node *p = head; p != NULL; p = p->next)
    sum += p->value;
```

节点可能散布在堆中，CPU 不容易提前知道下一个地址，缓存命中率较低。

因此即使二者时间复杂度都是：

[
O(n)
]

实际性能也可能差很多。

时间复杂度描述操作数量增长趋势，不能完整反映：

* 缓存命中；
* 分支预测；
* 指令并行度；
* 内存带宽；
* 数据布局。

# 四十八、从高级语言看一段完整例子

考虑：

```c
int sum_positive(const int *arr, int n) {
    int sum = 0;

    for (int i = 0; i < n; i++) {
        if (arr[i] > 0) {
            sum += arr[i];
        }
    }

    return sum;
}
```

假设使用 Windows x64 调用约定：

* `rcx`：`arr`；
* `edx`：`n`；
* `eax`：返回值。

一种简化汇编：

```asm
sum_positive:
    xor eax, eax            ; sum = 0
    xor r8d, r8d            ; i = 0

loop_test:
    cmp r8d, edx
    jge loop_end            ; i >= n 时退出

    mov r9d, DWORD PTR [rcx+r8*4]
    test r9d, r9d
    jle skip_add            ; arr[i] <= 0

    add eax, r9d            ; sum += arr[i]

skip_add:
    inc r8d                 ; i++
    jmp loop_test

loop_end:
    ret
```

逐项对应：

| 高级语言            | 汇编实现            |
| --------------- | --------------- |
| `sum = 0`       | `xor eax, eax`  |
| `i = 0`         | `xor r8d, r8d`  |
| `i < n`         | `cmp` + `jge`   |
| `arr[i]`        | `[rcx+r8*4]`    |
| `arr[i] > 0`    | `test` + `jle`  |
| `sum += arr[i]` | `add eax, r9d`  |
| `i++`           | `inc r8d`       |
| 循环              | `jmp loop_test` |
| 返回 `sum`        | `eax` + `ret`   |

这里已经包含了大多数高级语言基础结构：

* 变量；
* 数组；
* 指针；
* 表达式；
* 比较；
* `if`；
* `for`；
* 函数参数；
* 返回值。

# 四十九、`test` 指令是什么

汇编中经常看到：

```asm
test eax, eax
je zero
```

`test` 会执行按位与，但不保存结果，只设置标志位。

因为：

[
x\mathbin{&}x=x
]

所以：

```asm
test eax, eax
```

可以判断 `eax` 是否为 0。

等价目的：

```asm
cmp eax, 0
```

但编码和具体使用场景可能更合适。

# 五十、为什么经常用 `xor eax, eax` 清零

```asm
xor eax, eax
```

因为：

[
x\oplus x=0
]

所以这条指令将 `eax` 清零。

它通常比：

```asm
mov eax, 0
```

编码更短，并且现代 CPU 会专门识别这种清零惯用法，消除对旧 `eax` 值的依赖。

# 五十一、高级语言不同执行方式的区别

## C、C++、Rust

通常提前编译为本机机器码：

```text
源代码 → 编译器 → 机器码 → CPU
```

## Java、C#

通常先生成字节码或中间语言：

```text
Java 源代码
    ↓
JVM 字节码
    ↓
解释器或 JIT 编译器
    ↓
机器码
```

## Python、JavaScript

通常由解释器、虚拟机或 JIT 执行：

```text
源代码
    ↓
语法树或字节码
    ↓
虚拟机
    ↓
必要时 JIT
    ↓
机器码
```

即使是解释执行，解释器自身也是机器码。

例如 Python 计算：

```python
a + b
```

底层不只是一个 `add` 指令。它可能需要：

1. 判断 `a`、`b` 的动态类型；
2. 查找加法实现；
3. 处理大整数；
4. 分配结果对象；
5. 更新引用计数；
6. 检查异常。

所以高级动态语言的一次运算可能对应几十甚至几百条机器指令。

# 五十二、理解汇编时最重要的五层模型

学习时可以始终用下面五层分析一个语句。

## 第一层：语言语义

例如：

```c
x = arr[i] + 1;
```

语言规定：

* 读取 `arr[i]`；
* 加一；
* 保存到 `x`。

## 第二层：数据表示

* `arr` 是地址；
* `i` 是整数；
* 数组元素占 4 字节；
* `x` 是 32 位整数。

## 第三层：地址计算

[
\operatorname{address}(arr[i])
==============================

arr+i\times4
]

## 第四层：指令

```asm
mov eax, DWORD PTR [rcx+rdx*4]
add eax, 1
mov DWORD PTR [x], eax
```

## 第五层：微架构

* 数据是否命中缓存；
* 指令是否并行执行；
* 地址计算单元是否忙；
* 是否发生流水线停顿；
* 是否存在分支预测失败。

初学时先掌握前四层，第五层属于性能优化与计算机体系结构。

# 五十三、学习汇编最合适的顺序

建议按下面顺序学习：

1. 二进制、十六进制、补码和大小端；
2. 寄存器、内存、地址和指针；
3. `mov`、`lea`、`add`、`sub`、`imul`；
4. `cmp`、`test`、标志位和条件跳转；
5. `if`、`while`、`for`、`switch`；
6. 数组、结构体和指针运算；
7. 栈、函数调用和调用约定；
8. 浮点和 SIMD；
9. 编译器中间表示与优化；
10. 缓存、流水线、乱序执行和分支预测。

实践时可以编写很短的 C 函数，然后观察编译结果：

```c
int add(int a, int b) {
    return a + b;
}
```

```c
int max(int a, int b) {
    return a > b ? a : b;
}
```

```c
int sum(int *a, int n) {
    int result = 0;
    for (int i = 0; i < n; i++)
        result += a[i];
    return result;
}
```

学习重点不是死记每条指令，而是不断回答三个问题：

1. 当前数据放在哪里？
2. 当前指令改变了什么状态？
3. 下一条指令为什么会执行到那里？

真正掌握这三个问题后，高级语言中的变量、表达式、条件、循环、函数、数组、指针和对象就不再是彼此分散的语法，而会统一成：

[
\boxed{
\text{数据表示}
+
\text{地址计算}
+
\text{寄存器运算}
+
\text{控制流转移}
}
]
